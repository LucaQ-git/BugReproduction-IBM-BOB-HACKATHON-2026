The Big Picture

BugRep-AI takes a plain-English bug report and business rules, then runs a three-stage AI pipeline — writing tests, fixing the bug, and generating a report — entirely automatically via Bob Shell.

Root-level files

AGENTS.mdContext

Bob reads this file automatically at the start of every session. It tells Bob what this project is, where everything lives, the custom modes available, and the non-negotiable rules (never weaken assertions, never edit cart.fixture.js, etc.).

Think of it as the project's constitution — it's the single source of truth that keeps Bob oriented across all three stages.

README.mdDocumentation

Human-readable documentation. Covers prerequisites, quick-start commands, how to run each stage manually or automatically, Bob Shell installation, API key setup, and the test integrity policy. Also contains the future web-app integration plan.

SECURITY.MDPolicy

Security ground rules for the project: never hardcode API keys, always use environment variables, never paste credentials into Bob chat. Also contains code examples of the right and wrong way to handle credentials.

.bobignoreConfig

Tells Bob which files to never read or expose. Covers all API key patterns (*API_KEY*, *api_key*), .env files, and IBM Cloud credential patterns. This prevents Bob from accidentally seeing or leaking secrets.

.gitignoreConfig

Standard git ignore rules — excludes node_modules/, .env, *api-key*, *api_key*, and other credential-bearing file patterns from being committed.

bugrep-ai/orchestrator.js — The Controller

bugrep-ai/orchestrator.jsEntry Point

The main script. It is a coordinator, not an AI — it knows nothing about bugs. It has four operating modes:

CommandWhat it does
node orchestrator.jsReads state, prints the current stage, and prints the Bob chat prompt to paste for the next manual step.
node orchestrator.js --resetDeletes .workflow-state.json so you can start a fresh run.
node orchestrator.js --run-testsRuns Jest directly and records the result into state. Used manually between stages.
node orchestrator.js --autoFull automation. Invokes Bob Shell for all 3 stages in sequence via workflow/bob-runner.js, runs Jest for the RED and GREEN runs, and records everything.

The --auto path: resets state → calls Bob Shell (Test Agent) → runs Jest RED → checks bug reproduced → sets fixApproved: true → calls Bob Shell (Fix Agent) → runs Jest GREEN → calls Bob Shell (Report Agent) → marks stage: done.

bugrep-ai/workflow/ — Supporting Modules

bugrep-ai/workflow/state.jsState

Reads and writes .workflow-state.json. Every agent and the orchestrator use this — it's the shared memory of the entire run. Exposes three functions: load(), save(updates), and reset().

The state file tracks: run ID, timestamps, current stage, the bug report text, RED run results, whether the bug was reproduced, the proposed diff, fix approval status, GREEN run results, and report file paths.

bugrep-ai/workflow/runner.jsTest Runner

Runs Jest programmatically and returns a structured result object. Invokes Jest as node jest/bin/jest.js <file> --no-coverage --json — this avoids Windows .cmd wrapper issues that previously caused stdout to be dropped entirely.

Returns: { passed, failed, errorType, testResults, output, error }. The errorType is one of none / assertion / syntax / dependency / environment — this distinction is critical: only assertion failures count as a reproduced bug.

bugrep-ai/workflow/bob-runner.jsAutomation

New file added in this session. Invokes Bob Shell non-interactively for each agent stage. Reads the relevant agents/*.md instruction file and passes it as the prompt to bob run --trust <prompt>.

Requires BOBSHELL_API_KEY in the environment. If the key is missing, it returns a clear error immediately. Exports: runTestAgent(), runFixAgent(), runReportAgent().

bugrep-ai/workflow/inputs.jsLoader

Loads the three input documents — fixtures/bug_report.txt, docs/cart_rules.md, and src/cart.js — into a clean context object. Throws a clear error listing any missing files, so the orchestrator can fail fast with a useful message.

bugrep-ai/workflow/jira.jsStub

Jira integration — not yet connected. The code is written and commented out, ready to enable. Exports isConfigured() (checks for JIRA_BASE_URL, JIRA_USER_EMAIL, JIRA_API_TOKEN) and fetchIssue(issueKey) (throws "not configured" until enabled).

When connected, this would let you feed a Jira issue key instead of bug_report.txt as the workflow input.

bugrep-ai/agents/ — Bob's Instructions Per Stage

These Markdown files are the prompts fed to Bob Shell. Each one tells Bob exactly what its role is, what files to read, what steps to follow, and what it must never do.

bugrep-ai/agents/test-agent.mdStage 1

Instructions for the Test Agent. Bob reads this and then: reads the bug report + business rules, writes src/cart.test.js with 18 strict regression tests (using only toBe, toEqual, toThrow, toBeGreaterThanOrEqual), and runs them against cart.fixture.js (the buggy code) to produce the RED run.

Hard constraints: never modify cart.js, never weaken an assertion, never claim a bug is reproduced if the error is syntax or environment.

bugrep-ai/agents/fix-agent.mdStage 2

Instructions for the Fix Agent. Bob reads this and then: verifies the bug was reproduced (checks state), identifies the minimal code change, records the unified diff in proposedDiff in state, checks if fixApproved is already true (set by --auto mode) or waits for human approval, then writes the fix to src/cart.js.

In --auto mode, approval is pre-granted by the orchestrator so Bob proceeds immediately. In manual mode, Bob shows the diff and waits for "yes".

bugrep-ai/agents/report-agent.mdStage 3

Instructions for the Report Agent. Bob reads this and then produces two files in reports/: a human-readable Markdown report and a machine-readable JSON report. Every claim must be traceable to a real file or state entry — no speculation, no invented results.

The report covers: run metadata, the original bug report verbatim, reproduction evidence (test names + failure messages), root cause analysis with line numbers, the proposed diff, verification (all 18 tests passing), changed files, and remaining limitations.

bugrep-ai/src/ — The Actual Code Under Test

bugrep-ai/src/cart.fixture.jsREAD-ONLY · Never Edit

The permanently buggy 4-line implementation. This is intentionally broken and is the "before" snapshot. The Test Agent runs tests against this file to confirm the bug exists (RED run).

function calculateTotal(items, discountPercentage) {
  let subtotal = items.reduce((sum, item) => sum + item.price, 0);
  let discount = (subtotal * discountPercentage) / 100;
  return subtotal - discount;   // ← no guards, no validation, no clamping
}

Known defects: passes undefined discount straight into arithmetic (→ NaN), no clamp for >100% discount (→ negative total), no validation of item prices or discount type.

bugrep-ai/src/cart.jsProduction · Fixed

The patched production implementation. Written by the Fix Agent. Implements all 9 business rules: throws RangeError for NaN/Infinity discount, normalises undefined/null to 0%, clamps negative discounts, validates each item price, clamps total to ≥ 0, and rounds to 2 decimal places.

The GREEN run (18/18 passing) confirms this file satisfies every test in cart.test.js.

bugrep-ai/src/cart.fixture.test.jsRED run test file

18 tests that explicitly require('./cart.fixture'). This is the file the orchestrator runs for the RED run in --auto mode. Result: 12 failures, 6 passing — proving the bug exists before the fix is applied.

bugrep-ai/src/cart.test.jsGREEN run test file

18 tests that require('./cart') (the production file). Written by the Test Agent (or manually). This is the file run for the GREEN run after the fix is applied. Result: 18/18 passing. These tests become the permanent regression suite.

bugrep-ai/fixtures/ and bugrep-ai/docs/ — Inputs

bugrep-ai/fixtures/bug_report.txtInput

The plain-English bug report that triggers the entire workflow. Currently: "The cart total becomes incorrect or yields NaN/negative values when applying a discount to an empty cart or when items array is empty."

To run a different bug through the system, replace this file's content and run node orchestrator.js --reset && node orchestrator.js --auto.

bugrep-ai/docs/cart_rules.mdBusiness Rules

The authoritative source of truth. 9 rules governing how calculateTotal must behave. Both the Test Agent and Fix Agent read this — tests are written to assert these rules, and the fix must satisfy all of them.

#Rule
1Subtotals calculated from item prices
2Total never below 0 (discount clamp)
3Empty cart always returns 0
4Undefined discount → treat as 0%
5Negative discount → clamp to 0%
6NaN / ±Infinity discount → throw RangeError
7Missing / non-numeric item price → throw TypeError
8Negative item price → throw TypeError
9All totals rounded to 2 decimal places
