BugRep-AI

Automated bug reproduction and fix workflow — team overview
Powered by IBM Bob IDE
One sentence: You give it a bug report in plain English, and it automatically writes tests that prove the bug exists, proposes a fix for your approval, applies it, and generates a report — all driven by IBM Bob.

What problem does it solve?

Normally when someone reports a bug, a developer has to manually reproduce it, write a test, figure out the fix, and document it. BugRep-AI automates all of that using IBM Bob as the AI engine. The developer stays in control — they approve the fix before anything is applied.

How it works — step by step

1
You provide a bug report
A plain-English description of what's broken goes into fixtures/bug_report.txt. Business rules (what the code should do) live in docs/cart_rules.md. No special format needed.
Example: "The cart total becomes negative when a discount over 100% is applied."
2
Run the orchestrator
You run node orchestrator.js in the terminal. It loads your bug report and rules, then prints the exact prompt to paste into IBM Bob.
The orchestrator is a coordinator — it does not pretend to be AI. It loads files, runs tests, and tracks state.
3
🔴 Test Agent — Bob writes and runs tests
You paste the prompt into IBM Bob IDE. Bob reads the bug report and business rules, then writes strict tests against the buggy copy of the code. The tests are designed to fail — that's the point.
Bob runs Jest. Result: 6 passed, 12 failed — all assertion failures.
This proves the bug is real, not just a complaint.
4
🔧 Fix Agent — Bob proposes a fix
Bob reads the failing tests and the buggy code, identifies the root cause, and shows you a diff (the exact lines it wants to change) before touching anything.
You must approve the diff. Bob will not apply any fix without your explicit "approve" in the chat.
5
🟢 Fix applied and verified
After your approval, Bob applies the fix to the production file and reruns the same tests. All tests must pass — without changing a single assertion.
If tests still fail after the fix, Bob reports that honestly and stops. It does not retry silently or weaken the tests.
6
📋 Report Agent — Bob documents everything
Bob generates a Markdown and JSON report covering: the original bug, reproduction evidence, root cause, the diff, before/after test results, and any remaining limitations.
Reports are saved to reports/run-<id>.md and reports/run-<id>.json. Every claim is traceable to an actual file or run result.

The three IBM Bob agent roles

🔴
Test Agent
Reads the bug report and writes tests. Runs them against the broken code. Reports what actually failed.
🔧
Fix Agent
Uses the failures to find the root cause. Shows a diff for your approval. Applies it and verifies with a full test run.
📋
Report Agent
Reviews all run artifacts and produces a complete Markdown + JSON report from real data only.

The golden rule: Tests are never weakened to make them pass. The only valid fix is a correct implementation change. IBM Bob is explicitly instructed to refuse any approach that relaxes an assertion.

Commands to run it

# 1. Install dependencies (once)
$cd bugrep-ai && npm install
# 2. Check state and get the Bob prompt for the next stage
$node orchestrator.js
# 3. After Bob writes/applies, record the test result
$node orchestrator.js --run-tests
# 4. Start a fresh run
$node orchestrator.js --reset
