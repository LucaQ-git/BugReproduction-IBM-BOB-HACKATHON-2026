# BugRep-AI

> Automated bug reproduction and regression-patch workflow powered by **IBM Bob IDE**.

---

## What it does

Given a plain-English bug report, BugRep-AI runs a three-stage IBM Bob workflow:

| Stage | Bob custom mode | What happens |
|---|---|---|
| 1 — Test Agent | `bugrep-test` | Reads bug report + business rules, writes strict regression tests, runs them against the buggy fixture → **RED** |
| 2 — Fix Agent | `bugrep-fix` | Uses reproduction evidence to propose a minimal fix, shows you the diff for approval, applies it, reruns tests → **GREEN** |
| 3 — Report Agent | `bugrep-report` | Reviews actual run artifacts and produces `reports/run-<id>.md` + `.json` |

The orchestrator script is a **coordinator**, not a simulator — it loads inputs,
stores run state, runs Jest directly, and prints the exact Bob task prompt to
paste for each stage.  Analysis, test writing, and patch generation are done by
IBM Bob.

## Project structure

```
bugrep-ai/
├── agents/
│   ├── test-agent.md        ← Bob subtask instructions (Stage 1)
│   ├── fix-agent.md         ← Bob subtask instructions (Stage 2)
│   └── report-agent.md      ← Bob subtask instructions (Stage 3)
├── docs/
│   └── cart_rules.md        ← Authoritative business rules
├── fixtures/
│   └── bug_report.txt       ← Input bug report
├── reports/                 ← Generated by Report Agent
├── src/
│   ├── cart.js              ← Production implementation
│   ├── cart.fixture.js      ← Buggy reference (never edit)
│   └── cart.test.js         ← Regression test suite
├── workflow/
│   ├── inputs.js            ← Document loader
│   ├── runner.js            ← Jest runner (returns structured results)
│   ├── state.js             ← Run state (.workflow-state.json)
│   └── jira.js              ← Jira interface (not yet connected)
└── orchestrator.js          ← Workflow coordinator
```

## Prerequisites

- **Node.js ≥ 18** and **npm ≥ 9**
- **IBM Bob IDE** (enterprise or trial)
- The workspace opened in Bob IDE so the custom modes in `.bob/custom_modes.yaml` are loaded

### Additional prerequisites for `--auto` mode

- **Bob Shell** installed on your machine
- A **Bob API key** (Inference scope) set as `BOBSHELL_API_KEY`

#### Installing Bob Shell (Windows)

```powershell
powershell -ep Bypass 'irm -Uri "https://bob.ibm.com/download/bobshell.ps1" | iex'
```

#### Setting your API key

Get an Inference-scoped API key from the Bob web portal → Account → API Keys, then:

```powershell
# Temporary (current session only)
$env:BOBSHELL_API_KEY = "your-key-here"

# Permanent (persists across reboots)
[System.Environment]::SetEnvironmentVariable('BOBSHELL_API_KEY', 'your-key-here', 'User')
```

Or add it to `bugrep-ai/.env` (never commit this file):

```
BOBSHELL_API_KEY=your-key-here
```

You only need to accept the license agreement once:

```powershell
$env:BOBSHELL_API_KEY = "your-key-here"
bob run --accept-license "hello"
```

## Quick start

```bash
# 1. Install dependencies
cd bugrep-ai
npm install

# 2a. Manual mode — get the Bob IDE prompt for Stage 1
node orchestrator.js

# 2b. Automatic mode — run all 3 stages hands-free via Bob Shell
node orchestrator.js --auto
```

In manual mode, Bob IDE will print a prompt block. Copy it into the Bob chat panel.
In automatic mode, Bob Shell drives every stage without any human input.

## Running each stage

### Stage 1 — Test Agent (🔴 RED run)

1. In Bob IDE, switch to **🔴 BugRep Test Agent** mode (or use Agent mode).
2. Paste the prompt printed by `node orchestrator.js`.
3. Bob will read `agents/test-agent.md`, write `src/cart.test.js`, and ask to run tests.
4. After Bob finishes, run in the terminal:
   ```bash
   node orchestrator.js --run-tests
   ```
5. Re-run the orchestrator to confirm the bug was reproduced and get the Stage 2 prompt:
   ```bash
   node orchestrator.js
   ```

### Stage 2 — Fix Agent (🔧 Patch + 🟢 GREEN run)

1. Switch to **🔧 BugRep Fix Agent** mode (or use Agent mode).
2. Paste the prompt printed by the orchestrator.
3. Bob reads `agents/fix-agent.md`, reads `.workflow-state.json`, and shows you a diff.
4. **Review and approve (or reject) the diff** in the Bob chat panel.
5. Once you approve, Bob applies the fix and asks to run tests:
   ```bash
   node orchestrator.js --run-tests
   ```
6. Re-run the orchestrator:
   ```bash
   node orchestrator.js
   ```

### Stage 3 — Report Agent (📋 Report)

1. Switch to **📋 BugRep Report Agent** mode (or use Agent mode).
2. Paste the prompt printed by the orchestrator.
3. Bob reads `agents/report-agent.md` and all artifacts, then writes:
   - `reports/run-<id>.md`
   - `reports/run-<id>.json`

### Automatic mode (all stages at once)

Requires Bob Shell + `BOBSHELL_API_KEY` (see [Prerequisites](#additional-prerequisites-for---auto-mode)):

```bash
cd bugrep-ai
node orchestrator.js --auto
```

The orchestrator will:
1. Reset state and start a fresh run
2. Invoke Bob Shell → **Test Agent** writes `src/cart.test.js` and runs Jest (RED)
3. Invoke Bob Shell → **Fix Agent** patches `src/cart.js` and runs Jest (GREEN)
4. Invoke Bob Shell → **Report Agent** writes `reports/run-<id>.md` + `.json`

All output is printed to the terminal in real time.  If any stage fails, the
workflow stops and records the failure in `.workflow-state.json`.

## Example task prompt for Bob

Paste this into the Bob IDE chat to start Stage 1 from scratch:

```
Read bugrep-ai/agents/test-agent.md and start a new subtask following those
instructions exactly.  The bug report is in bugrep-ai/fixtures/bug_report.txt
and the business rules are in bugrep-ai/docs/cart_rules.md.
Test against bugrep-ai/src/cart.fixture.js (the buggy implementation).
Do NOT modify bugrep-ai/src/cart.js.
```

---

## Resetting the workflow

```bash
node orchestrator.js --reset
```

This deletes `.workflow-state.json` so you can start a fresh run.
It does **not** overwrite `src/cart.js` or `src/cart.test.js`.

## Jira integration (future)

Manual bug entry works without Jira.  To enable Jira later:

1. Add to `.env` (never commit this file):
   ```
   JIRA_BASE_URL=https://your-org.atlassian.net
   JIRA_USER_EMAIL=you@example.com
   JIRA_API_TOKEN=<token>
   JIRA_PROJECT_KEY=PROJ
   ```
2. Follow the setup instructions in `workflow/jira.js`.
3. The orchestrator will show **✅ Jira configured** on startup.

Bob will always ask before fetching an issue and will show you the issue content
before using it as a bug report input.

## Test integrity policy

- Assertions in `src/cart.test.js` use `toBe`, `toEqual`, `toThrow`, or
  `toBeGreaterThanOrEqual` — never relaxed to make a test pass artificially.
- `src/cart.fixture.js` is read-only — it is the permanent buggy reference used
  for RED runs.
- The Fix Agent may only write to `src/cart.js` after you approve the diff (manual mode),
  or after the orchestrator sets `fixApproved: true` in state (auto mode).

## Future web app integration

The workflow is designed to be reusable from a web backend:

| Layer | Mechanism |
|---|---|
| Input submission | POST bug report + rules to a backend endpoint |
| Stage execution | Backend calls `bob --auth-method api-key --yolo -p "..."` per stage |
| Progress events | Bob Shell stdout streamed to frontend via SSE |
| Diff approval | In `--auto` mode, approval is set in state; in manual mode the user approves in chat |
| Artifact download | Backend serves `reports/` directory |

**What works today** vs **what needs additional setup:**

| Feature | Manual (IDE) | Auto (`--auto`) | Web app (future) |
|---|---|---|---|
| Test writing by Bob | ✅ | ✅ via Bob Shell | Needs Bob Shell on server |
| Fix generation by Bob | ✅ | ✅ via Bob Shell | Needs Bob Shell + `BOBSHELL_API_KEY` |
| Jest runs | ✅ | ✅ | ✅ (node orchestrator.js --run-tests) |
| Report generation | ✅ | ✅ via Bob Shell | Needs Bob Shell |
| Jira fetch | ❌ not yet | ❌ not yet | Needs JIRA_* env vars |
| Multi-repo support | Manual | Manual | Needs repo selector UI |
